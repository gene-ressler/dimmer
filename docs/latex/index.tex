\chapter{Wireless 0-\/10 volt lignt dimmer}

\hypertarget{index_autotoc_md0}{}\doxysection{\texorpdfstring{Design and implementation notes}{Design and implementation notes}}\label{index_autotoc_md0}
This design is for the case of 0-\/10 volt dimmable fixtures controlled by multiple switches replacing old fixtures that either weren\textquotesingle{}t dimmable or used mains dimming, e.\+g. standard triac-\/based devices. Therefore either new 0-\/10 volt wiring or a wireless solution is needed. This project is about the second approach.

It is my first ESP32 project. All feedback is very welcome. Be kind.\hypertarget{index_autotoc_md1}{}\doxysubsection{\texorpdfstring{Goals}{Goals}}\label{index_autotoc_md1}

\begin{DoxyItemize}
\item Retain existing on/off switches. No mains power switching by the dimmer.
\begin{DoxyItemize}
\item Avoids safety considerations and complexity.
\end{DoxyItemize}
\item Receiver (rx) box at each light running on switched light power, producing the 0-\/10 volt control.
\item Transmitter (tx) box with a knob at each switch (or anywhere else). Twisting any changes the 0-\/10 volt output of all receivers.
\item No batteries. Mains power for all boxes.
\item Secure\+: Reasonably proof against playback and spoofing attacks.
\item Power interruption resilience\+: doesn\textquotesingle{}t lose dimming level and keeps working.
\end{DoxyItemize}\hypertarget{index_autotoc_md2}{}\doxysubsection{\texorpdfstring{Approach}{Approach}}\label{index_autotoc_md2}

The module {\ttfamily \doxylink{shared_8c}{shared.\+c}/h} houses data touched by several threads, therefore implemented with {\ttfamily \texorpdfstring{$<$}{<}stdatomic.\+h\texorpdfstring{$>$}{>}}. These are exactly sufficient for power fail resilience checkpoints.


\begin{DoxyItemize}
\item Broadcast sequence number
\item Current dimmer level

There is another small block of data protected by mutex in {\ttfamily \doxylink{wifi_8c}{wifi.\+c}}. It contains state for sending broadcasts repeatedly. The triggering thread sets up this data while holding the mutex, then wakes up the repeat thread, which iterates the requested number of times, grabbing the mutex to ensure no races with triggering threads.\hypertarget{index_autotoc_md7}{}\doxysubsection{\texorpdfstring{Rx driver circuit}{Rx driver circuit}}\label{index_autotoc_md7}
There are two options\+: one that will always work and another depends on a particular implementation of the driven lights.

Both options start with a 2-\/pole RC low pass filter to convert the 3.\+3 volt PWM output to a 0-\/3.\+3 volt DC signal. "{}\+Soft start"{} is also desired\+: forcing a 0v output for about one second while the receiver boots and sets up the PWM output at turn-\/on time.\hypertarget{index_autotoc_md8}{}\doxysubsubsection{\texorpdfstring{All purpose option}{All purpose option}}\label{index_autotoc_md8}
Use a standard 3.\+03x non-\/inverting op amp circuit (LM385 or similar) to convert 0-\/3.\+3 volts to 0-\/10. The op amp requires a 12 volt supply in this case, while the ESP32 needs either 3.\+3 or 5 volts. A dual voltage supply is necessary.\hypertarget{index_autotoc_md9}{}\doxysubsubsection{\texorpdfstring{Pulled inputs option}{Pulled inputs option}}\label{index_autotoc_md9}
If the controlled lights have a 10v (or more) default potential across the control line, then the op amp can drive a BJT that serves only to draw down this potential to the dimming level. A 1\+:3 voltage divider in the feedback loop lets the op amp bias the transistor properly using only a 5-\/volt supply. This is handy, as it allows receivers to work with a single rather than dual voltage supply.
